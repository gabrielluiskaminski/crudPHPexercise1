Explicação da execução do fluxo do código.

Preciso explicar o fluxo de execução deste codigo, vou escrever e voce analisa o que eu errei:
Primeiramente nos temos o compose.yaml que vai construir os dois container com as imagens que vão ser criadas a partir dos dois Dockerfiles em frontend e backend.
No Dockerfile do backend ele vai construir o contaifner criando uma imagem que ja vem o php 8.3 cli instalado e vai usar a pasta /app. Na pasta app ele vai copiar os arquivos config, public, src e data para dentro da pasta e vai dar permissão para todos lerem, escreverem e executarem a pasta data. Apos isso vai usar o expose para indicar a porta que vai ser usada que é a 80 e vai rodar o comando no cmd php -S 0.0.0.0:80 -t public public/index.php que vai ordenar o container para usar a porta 80 para comunicação e executar o servidor php. O -t vai tornar a pasta public como root do programa e vai indicar o index.php para começar o programa quando aparecer uma requisição.
quando chamado o index.php vai primeiramente buscar pelo caminho literal e incluir os arquivos do config.php, apos vai criar a variavel origin que vai receber do array associativo o valor da chave ['HTTP_ORIGIN'], caso não tenha nenhum valor vai receber apenas uma aspas simples. Apos ele vai executar um operador ternario que verifica se o valor de $origin está em $allowedOrigins que esta no config.php, e se for verdade ele envia um cabeçalho HTTP liberando um acesso desta origem especifica para o navegador. Depois disso ele define os metodos aceitos no cabeçalho, o tipo de resposta que o servidor espera do navegador e o tipo do body da resposta HTTP. Depois disso ele verifica se o metodo de requisição HTTP é options e se for options ele define o status code do cabeçalho da resposta HTTP com 204 e encerra a execução do código, esse if so serve para o navegador saber se pode conversar com a api e o retorno disso não tem body, so o cabeçalho com o status code 204.
Caso o metodo HTTP não seja OPTIONS o código vai seguir e criar uma variavel que recebe a URI da URL, cortando os query params que estão apos a interrogação e vai usar essa uri para ver se ela é compatível no match, se for diferente de /api/users vai chamar a função notFound que define o status code como 404 no cabeçalho da resposta HTTP e define o body da resposta com o array associativo chave 'error' valor 'Not found' que vai ser convertido em JSON.
Se for igual a /api/users vai incluir e executar o arquivo api.php na pasta src, usando o caminho literal. A execução do api.php começa incluindo o código em /controllers.php para usar as funções no match. A váriavel $method recebe o valor que está no array associativo $\_SERVER['REQUEST_METHOD'], para ser usada no match buscando o método correto. Caso não encontre nenhum dos métodos aceitos vai para o default e executa a função handleMethodNotAllowed. A função apenas retorna o status code 405 e o body como JSON error:Method not allowed.
Caso seja o método GET a função handleGet vai ser chamada e vai executar um try/catch. Ela vai tentar chamar a função respond com parametro a resposta da função getAllUsers que vai criar a variavel $data que recebe a resposta da função loadData que vai inicialmente verificar com um if se DATA_FILE que está no config.php não é um arquivo, se não for um arquivo ele retorna a função emptyData que retorna um array associativo com a chave 'users' com valor um array vazio e a chave 'nextId' com valor 1. caso seja um arquivo ele vai criar a variavel $content que recebe uma string do file_get_contents, que le o DATA_FILE e retorna uma string no formato JSON. Caso ele nao consiga receber a string ele recebe um false e retorna o array em emptyData.
Caso funcione é criada a variavel $data que recebe o JSON convertido em array associativo com o json_decode true, e apos verifica se $data é diferente de um array ou se as chaves 'users' ou 'nextId' não são definidas, se não forem retorna o array da função emptyData, se tudo estiver certo ele devolve o próprio $data que contém o array associativo para a função getAllUsers, que vai retornar um array associativo para a função respond que vai pegar o status code desse array e caso tenha algum erro definido vai converter o erro para JSON e envia-lo para o body da resposta e se nao tiver nenhuma chave 'error' definida vai converter o que está na chave 'data' para JSON e envia-lo para o body da resposta.
Caso seja POST ele chama a função handlePost que vai usar um try/catch chamando a função respond que recebe o retorno da função createUser que recebe o retorno de readJsonBody que retorna ou nulo ou a variavel $input.
O file_get_contents usa o php://input que é um stream do php que le o corpo do body da requisição e retorna ou uma string com formato JSON ou false e json_decode converte a string em formato JSON retornada pelo file_get_contents em um array associativo.
Na createUser se a readJsonBody retornar null a função já retorna um array contendo o erro, se não cria a variavel $erro que recebe o retorno da função validateRequiredFields, passando como parametro o array associatido de readJsonBody e um array com strings para verificar se os valores das chaves existem e não estão nulos. Caso algum valor seja nulo ele retorna o erro para respond, se tudo estiver certo ele retorna null e faz o mesmo teste com validateUserFields para validar se todos os valores das chaves foram preenchidos corretamente como não ter string vazias ou idades acima de 150. Caso não de nenhum erro ele cria uma variavel $user que recebe o retorno da função insertUser.
A função insertUser vai chamar withDataLock que recebe como parametro uma função anonima.
withDataLock vai criar uma variavel que vai receber um arquivo aberto pelo fopen, sendo usado o caminho para o arquivo o DATA_FILE e o comando 'c' abre o arquivo, e caso ele não exista cria ele. O 'c' não apaga o arquivo caso ele já exista.
Caso ele não consiga abrir o arquivo ele retorna false e entra no if que lança uma exceção que o catch do handlePost recebe e executa a função respondServerError que vai enviar o detalhe do erro para o error_log, definir o status code como 500 e retorna para o navegador o JSON com chave 'error' e valor 'Internal server error'.
Caso $lock receba o arquivo aberto ela vai para o try/finally que tenta bloquear o arquivo para não haver outras modificações simultaneas, se falhar vai jogar uma exceção para o catch do handlePost novamente, e se der certo executa a função anonima que withDataLock recebeu. A função anonima vai ter a variavel $data que recebe o array associativo de loadData e apos isso faz o $id receber o 'nextId' atual, e apos somando mais um ao 'nextId'. depois faz o $user receber o $id atual e insere o $user criado no array associativo e $data, apos isso vai chamar a função saveData passando $data como parametro e retorna user. a função saveData vai pegar o $data e vai converter para JSON, respeitando a legibilidade humana e mantendo as acentuações com JSON_PRETTY_PRINT e JSON_UNESCAPED_UNICODE respectivamente. Após ele vai gravar no arquivo indicado por DATA_FILE o JSON de $data.
Após vai ser retornado o $user para withDataLock que vai retornar $user para o createUser que retorna o array associativo com chave 'data', valor $user e chave 'status', valor 400 para o respond em handlePost. A função withDataLock finalmente libera o arquivo e fecha o mesmo.
O createUser vai retornar para a respond o array associativo com o user e o status code que vai enviar para o navegador o JSON com o usuario no body e o status code no cabeçalho da resposta http.
